### 6.6.3 Fundamento Matemático del Motor de Inferencia

El motor de reconocimiento facial de V-ESCOM opera sobre un espacio vectorial de alta dimensionalidad. Al procesar una imagen, ArcFace (InsightFace, modelo `buffalo_l`) extrae un vector de características de 512 dimensiones, conocido como embedding facial. Antes de comparar dos rostros, el sistema aplica una normalización L2 para asegurar que cada vector tenga magnitud unitaria, es decir, que cumpla $\|\mathbf{x}\| = 1$.

La arquitectura utiliza dos estrategias matemáticas complementarias:

A. Búsqueda geométrica por similitud coseno

Cuando el sistema trabaja en modo rápido o cuando el modelo predictivo no está disponible, se recurre a la similitud coseno entre el embedding entrante $\mathbf{v}$ y los embeddings almacenados $\mathbf{u}$. Dado que ambos vectores están normalizados, la comparación se reduce al producto escalar:

$$
\cos(\theta) = \mathbf{u} \cdot \mathbf{v} = \sum_{i=1}^{512} u_i v_i
$$

Si el valor obtenido supera el umbral configurado en `SIMILITUD_UMBRAL_COSENO` (por defecto 0.40 en el servicio), el acceso se clasifica como autorizado. Este método es eficiente porque la comparación se ejecuta directamente en PostgreSQL con `pgvector`, sin cargar todos los vectores en memoria.

Fragmento de implementación:

```python
_face_app: Optional[FaceAnalysis] = None

def _get_face_app() -> FaceAnalysis:
  global _face_app
  if _face_app is None:
    _face_app = FaceAnalysis(name="buffalo_l")
    _face_app.prepare(ctx_id=-1, det_size=(640, 640))
  return _face_app

def similitud_coseno(vec_a: np.ndarray, vec_b: np.ndarray) -> float:
  vec_a = normalizar_l2(vec_a)
  vec_b = normalizar_l2(vec_b)
  return float(np.dot(vec_a, vec_b))
```

Este bloque resume dos ideas clave: la carga diferida del modelo ArcFace y la comparación geométrica mediante producto escalar sobre vectores ya normalizados.

B. Clasificación estadística con Máquina de Vectores de Soporte

Para mejorar la robustez frente a variaciones de pose, iluminación y oclusión parcial, el sistema entrena un clasificador SVM multiclase sobre los embeddings registrados. La función de decisión de la SVM busca separar las clases con el hiperplano de mayor margen:

$$
f(\mathbf{x}) = \operatorname{sign}(\mathbf{w} \cdot \mathbf{x} + b)
$$

Donde $\mathbf{x}$ representa el nuevo embedding, $\mathbf{w}$ el vector de pesos y $b$ el sesgo aprendido durante el entrenamiento. Para capturar fronteras de decisión no lineales, el pipeline integra un kernel RBF, definido por:

$$
K(\mathbf{x}, \mathbf{x}') = \exp\left(-\gamma \|\mathbf{x} - \mathbf{x}'\|^2\right)
$$

Este enfoque permite agrupar múltiples capturas de una misma persona en regiones de confianza más amplias, reduciendo falsos rechazos durante la identificación en tiempo real. En el modo `auto`, el backend usa la SVM si el archivo `modelos/clasificador_svm.joblib` está disponible; de lo contrario, cae al método por coseno.

Fragmento del flujo de entrenamiento:

```python
pipeline = Pipeline([
  ("normalizador", Normalizer(norm="l2")),
  ("clasificador", SVC(
    C=_SVM_PARAM_C,
    kernel=_SVM_KERNEL,
    probability=True,
    random_state=_SVM_SEMILLA,
    class_weight="balanced",
  )),
])
```

Aquí se observa la estructura que convierte el problema de reconocimiento en una clasificación supervisada: primero normaliza los embeddings y luego entrena una SVM con kernel RBF para capturar fronteras no lineales.

### 6.6.4 Dataset y Enrolamiento (operativo)

Descripción breve
- El módulo de reconocimiento utiliza embeddings faciales de 512 dimensiones extraídos con ArcFace
  (InsightFace). Las imágenes de referencia se almacenan en `BACKEND/fotos_rostros/` y los embeddings
  se persisten en la tabla `rostros_autorizados` (pgvector/VECTOR(512)).

Estructura de carpetas aceptada
- Carpetas por `id_persona`: `fotos_rostros/<id_persona>/imagen1.jpg`.
- O archivos con prefijo: `fotos_rostros/<id_persona>_imagen1.jpg`.

Formato y reglas
- Formatos soportados: `.jpg`, `.jpeg`, `.png`, `.jfif`.
- Regla clave: "una cara por imagen". La función `extraer_embedding` falla si hay 0 o >1 rostros.
- Nombre de archivo recomendado: `{id_persona}_{descripcion}.{ext}` para trazabilidad.

Proceso de enrolamiento
- Opción A (manual): mediante el endpoint `POST /reconocimiento/personas/{id_persona}/rostro`.
  - Envia `UploadFile` con la imagen; el servicio valida, extrae embedding y lo guarda.
- Opción B (por lote): usar el script

```bash
# desde la carpeta BACKEND con el venv activado
python entrenamiento/registrar_rostros_lote.py --dir fotos_rostros

# Forzar inserción a pesar de duplicados detectados
python entrenamiento/registrar_rostros_lote.py --dir fotos_rostros --forzar
```

Notas operativas
- Asegúrate de que la persona exista previamente en el catálogo (`personas_autorizadas`) antes
  de ejecutar el registro por lote; el script omitirá imágenes para `id_persona` no registrados.
- El registro valida duplicados biométricos usando `pgvector` y `cosine_distance`; si se detecta
  una similitud >= `SIMILITUD_UMBRAL` (por defecto `0.40`) se retorna `409 Conflict` salvo que se
  indique `?forzar=true`.
- El endpoint de identificación admite `modo=coseno` para la prueba rápida y `modo=svm` cuando ya
  exista un modelo entrenado; si no se indica nada, usa `modo=auto`.

Fragmento del registro con validación de duplicados:

```python
if not forzar:
  distancia = RostroAutorizado.embedding.cosine_distance(embedding.tolist())
  duplicado = (
    db.query(RostroAutorizado, PersonaAutorizada, distancia.label("distancia"))
    .join(PersonaAutorizada, PersonaAutorizada.id_persona == RostroAutorizado.id_persona)
    .filter(RostroAutorizado.id_persona != id_persona)
    .order_by(distancia)
    .first()
  )
  if duplicado:
    _, p_existente, dist_val = duplicado
    sim = 1.0 - float(dist_val)
    if sim >= SIMILITUD_UMBRAL:
      raise HTTPException(status_code=409, detail={...})
```

Este bloque es el corazón del enrolamiento: evita registrar dos identidades distintas con rasgos demasiado similares y obliga al operador a revisar el caso antes de continuar.

### 6.6.5 Entrenamiento del clasificador (operativo)

Objetivo
- Entrenar un clasificador supervisado (SVM) sobre los embeddings almacenados para realizar
  identificación rápida y obtener probabilidades/confianza en la predicción.

Dependencias
- Python packages: `scikit-learn`, `joblib`, `numpy`.
- Requisitos del sistema: `insightface` y `onnxruntime` para generar embeddings (si vas a extraer
  nuevos embeddings localmente).

Comando de entrenamiento (ejemplo)

```bash
python entrenamiento/entrenar_clasificador.py --salida modelos/clasificador_svm.joblib
```

Salida esperada
- Archivo `.joblib` que contiene el pipeline entrenado y el codificador de etiquetas.
- Imprime en consola el `classification_report` con precision/recall/f1 por clase y los resultados de
  validación cruzada si se ejecuta con CV.

Fragmento del entrenamiento real:

```python
codificador = LabelEncoder()
etiquetas = codificador.fit_transform(vector_y)
pipeline = _crear_pipeline()
pipeline.fit(matriz_x, etiquetas)
joblib.dump(artefacto, _RUTA_MODELO_SVM)
```

Aquí se codifican las personas como clases numéricas, se entrena el modelo con todos los embeddings disponibles y luego se guarda el artefacto para reutilizarlo en inferencia.

Dónde guardar el artefacto
- Recomendación: `BACKEND/modelos/` o almacenamiento externo (S3/Blob). **No** versionar binarios
  en el repositorio; añade `BACKEND/modelos/` a `.gitignore`.

Buenas prácticas
- Reentrenar el clasificador cada vez que se añadan un número significativo de nuevas personas
  o embeddings (p. ej. cada 100 nuevos embeddings o en un calendario mensual).
- Documentar la versión del clasificador (nombre con fecha): `clasificador_svm-YYYYMMDD.joblib`.

### 7.5.2 Entrenamiento y evaluación (Pruebas del módulo de reconocimiento facial)

Procedimiento de validación
- División de datos: CV estratificada por defecto (o split train/test 80/20 según configuración).
- Codificar etiquetas con `LabelEncoder` para convertir `id_persona` a clases 0..K-1.

Métricas a reportar
- Número total de embeddings y muestras por clase (media, mediana, min, max).
- `precision`, `recall`, `f1-score` por clase (presentado en `classification_report`).
- Matriz de confusión y, si procede, curva ROC/PR para clases relevantes.

Criterios de aceptación (ejemplos)
- Precisión macro promedio >= 0.75 para un dataset balanceado.
- Ninguna clase crítica con recall < 0.60 (ajustable según el contexto operativo).
  (Definir umbrales reales con el equipo operativo).

Tests de humo (reproducibles)
- Test 1: `extraer_embedding` con imagen de prueba que contenga exactamente un rostro — debe
  devolver un vector de dimensión 512 (sin excepciones).
- Test 2: ejecutar `entrenamiento/entrenar_clasificador.py` con un conjunto pequeño de embeddings de
  prueba y verificar que se genera el `.joblib` y que `classification_report` contiene métricas legibles.
- Test 3: probar el endpoint `POST /reconocimiento/identificar?modo=coseno` para confirmar que el
  sistema usa el camino rápido aunque exista un modelo SVM cargado.
