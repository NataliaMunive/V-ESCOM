## 6.6 Módulo de reconocimiento facial y dashboard

Este documento complementa la sección 6.6 del reporte técnico y contiene las subsecciones operativas
relacionadas con el dataset, el enrolamiento y el entrenamiento del clasificador.

### 6.6.3 Dataset y Enrolamiento (operativo)

Descripción breve
- El módulo de reconocimiento utiliza embeddings faciales de 512 dimensiones extraídos con ArcFace
  (InsightFace). Las imágenes de referencia se almacenan en `BACKEND/fotos_rostros/` y los embeddings
  se persisten en la tabla `rostros_autorizados` (pgvector/VECTOR(512)).

Estructura de carpetas aceptada
- Carpetas por `id_persona`: `fotos_rostros/<id_persona>/imagen1.jpg`.
- O archivos con prefijo: `fotos_rostros/<id_persona>_imagen1.jpg`.

Formato y reglas
- Formatos soportados: `.jpg`, `.jpeg`, `.png`, `.jfif`.
- Regla clave: "una cara por imagen". La función `extraer_embedding` falla si hay 0 o >1 rostros.
- Nombre de archivo recomendado: `{id_persona}_{descripcion}.{ext}` para trazabilidad.

Proceso de enrolamiento
- Opción A (manual): mediante el endpoint `POST /reconocimiento/personas/{id_persona}/rostro`.
  - Envia `UploadFile` con la imagen; el servicio valida, extrae embedding y lo guarda.
- Opción B (por lote): usar el script en español:

```bash
# desde la carpeta BACKEND con el venv activado
python entrenamiento/registrar_rostros_lote.py --dir fotos_rostros

# Forzar inserción a pesar de duplicados detectados
python entrenamiento/registrar_rostros_lote.py --dir fotos_rostros --forzar
```

Notas operativas
- Asegúrate de que la persona exista previamente en el catálogo (`personas_autorizadas`) antes
  de ejecutar el registro por lote; el script omitirá imágenes para `id_persona` no registrados.
- El registro valida duplicados biométricos usando `pgvector` y `cosine_distance`; si se detecta
  una similitud >= `SIMILITUD_UMBRAL` (por defecto `0.40`) se retorna `409 Conflict` salvo que se
  indique `?forzar=true`.
- El endpoint de identificación admite `modo=coseno` para la prueba rápida y `modo=svm` cuando ya
  exista un modelo entrenado; si no se indica nada, usa `modo=auto`.

### 6.6.4 Entrenamiento del clasificador (operativo)

Objetivo
- Entrenar un clasificador supervisado (SVM) sobre los embeddings almacenados para realizar
  identificación rápida y obtener probabilidades/confianza en la predicción.

Dependencias
- Python packages: `scikit-learn`, `joblib`, `numpy`.
- Requisitos del sistema: `insightface` y `onnxruntime` para generar embeddings (si vas a extraer
  nuevos embeddings localmente).

Comando de entrenamiento (ejemplo)

```bash
python entrenamiento/entrenar_clasificador.py --salida modelos/clasificador_svm.joblib
```

Salida esperada
- Archivo `.joblib` que contiene el pipeline entrenado y el codificador de etiquetas.
- Imprime en consola el `classification_report` con precision/recall/f1 por clase y los resultados de
  validación cruzada si se ejecuta con CV.

Dónde guardar el artefacto
- Recomendación: `BACKEND/modelos/` o almacenamiento externo (S3/Blob). **No** versionar binarios
  en el repositorio; añade `BACKEND/modelos/` a `.gitignore`.

Buenas prácticas
- Reentrenar el clasificador cada vez que se añadan un número significativo de nuevas personas
  o embeddings (p. ej. cada 100 nuevos embeddings o en un calendario mensual).
- Documentar la versión del clasificador (nombre con fecha): `clasificador_svm-YYYYMMDD.joblib`.

### 7.5.2 Entrenamiento y evaluación (Pruebas del módulo de reconocimiento facial)

Procedimiento de validación
- División de datos: CV estratificada por defecto (o split train/test 80/20 según configuración).
- Codificar etiquetas con `LabelEncoder` para convertir `id_persona` a clases 0..K-1.

Métricas a reportar
- Número total de embeddings y muestras por clase (media, mediana, min, max).
- `precision`, `recall`, `f1-score` por clase (presentado en `classification_report`).
- Matriz de confusión y, si procede, curva ROC/PR para clases relevantes.

Criterios de aceptación (ejemplos)
- Precisión macro promedio >= 0.75 para un dataset balanceado.
- Ninguna clase crítica con recall < 0.60 (ajustable según el contexto operativo).
  (Definir umbrales reales con el equipo operativo).

Tests de humo (reproducibles)
- Test 1: `extraer_embedding` con imagen de prueba que contenga exactamente un rostro — debe
  devolver un vector de dimensión 512 (sin excepciones).
- Test 2: ejecutar `entrenamiento/entrenar_clasificador.py` con un conjunto pequeño de embeddings de
  prueba y verificar que se genera el `.joblib` y que `classification_report` contiene métricas legibles.
- Test 3: probar el endpoint `POST /reconocimiento/identificar?modo=coseno` para confirmar que el
  sistema usa el camino rápido aunque exista un modelo SVM cargado.

Comandos para reproducir experimento básico

```bash
# 1) Registrar un conjunto pequeño de imágenes (ya en fotos_rostros)
python entrenamiento/registrar_rostros_lote.py --dir fotos_rostos

# 2) Entrenar el clasificador y guardar el artefacto
python entrenamiento/entrenar_clasificador.py --salida modelos/clasificador_svm.joblib

# 3) Cargar el artefacto y probar una predicción (ejemplo en Python REPL)
```
